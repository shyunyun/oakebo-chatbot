# Oakland Ebonics Dilemma Chatbot
### RDF-based Historical Decision Simulation

> **1996년 Oakland Ebonics 논쟁에서 Jesse Jackson이 처한 선택 상황을 데이터셋을 통해 단계적으로 탐색하고, 실제 역사적 선택을 알기 전에 스스로 판단해 보는 역사적 의사결정 시뮬레이션 챗봇입니다.**  
> *(A dataset-grounded historical decision simulation chatbot that lets users explore the 1996 Oakland Ebonics controversy from Jesse Jackson’s decision-making position, without revealing his actual historical choice until the user makes their own decision.)*

---

## 1. Project Overview

**Oakland Ebonics Dilemma**는 1996년 오클랜드 에보닉스(Oakland Ebonics) 논쟁 당시 민권운동가 제시 잭슨(Jesse Jackson) 목사가 직면했던 복잡한 수사적·도덕적 선택 상황을 RDF(Resource Description Framework) 데이터셋으로 구조화하고, 이를 바탕으로 사용자가 당시의 맥락을 단계적으로 탐색한 뒤 스스로 선택을 내려보는 **역사적 의사결정 시뮬레이션 챗봇**입니다.

본 프로젝트의 챗봇은 Jesse Jackson이라는 역사적 인물의 인격이나 실제 내면 심리를 AI가 어설프게 연기(Role-playing)하는 시스템이 아닙니다. 대신 챗봇은 **사건 밖의 객관적인 제3자 해설자** 시점을 유지하며, 사용자가 당시의 정보와 쟁점을 바탕으로 독립적인 판단을 내릴 수 있도록 돕습니다.

---

## 2. Dataset Purpose

본 데이터셋의 목적은 단순히 사건을 시간순으로 나열하는 일차원적 연표 작성이 아닙니다. **누가 어떤 주장을 했는지, 어떠한 선택지와 사건이 존재했는지, 그리고 그 내용이 어떤 1차 기록물(문서 및 기사)에 근거하는지**를 체계적으로 연결하고 추적하는 데 있습니다.

데이터셋은 다음 8가지 핵심 클래스로 구성되어 지식 그래프(Knowledge Graph)를 형성합니다:
- **클래스(Classes)**: `Person`, `Organization`, `Document`, `Event`, `Claim`, `Concept`, `Dilemma`, `Option`

또한 다음과 같은 명확한 시맨틱 관계(Relations)를 통해 사건·주장·근거의 입체적 관계를 추적합니다:
- `hasClaimant`: 주장의 주체를 연결
- `isEvidenceFor`: 문서/기사가 어떤 주장의 근거가 되는지 명시
- `hasOption`: 딜레마에 연결된 선택지 정의
- `isRealizedBy`: 선택이 실제 어떤 역사적 사건으로 구현되었는지 연결
- `precedes`: 사건 간의 시간적 선후 관계 기술

---

## 3. Why RDF?

줄거리 요약이나 단순 텍스트 파일 대신 **RDF 온톨로지 구조**를 채택한 핵심 이유는 **'객관적 사실(Fact)', '인물/기관의 주장(Claim)', '1차 기록물(Document)', '작업자의 해석(Interpretation)'을 엄격히 분리**할 수 있기 때문입니다.

### 💡 대표 예시: Ebonics의 언어적 지위
- 오클랜드 교육위원회의 원 결의안에 포함된 *"Ebonics는 영어의 방언이 아니다"*라는 구절을 데이터셋의 단정적 객관 사실로 저장하지 않습니다.
- 대신 이를 **오클랜드 교육위원회가 제기한 주장(`Claim`)**으로 저장하고, 원 결의안 문서(`Document`)를 `isEvidenceFor` 관계로 연결합니다.
- 이러한 정보의 분리와 출처 명시는 챗봇이 편향되거나 주관적인 주장을 객관적 사실처럼 설명하는 오류(Hallucination)를 방지하며, 응답의 **학술적 신뢰성과 투명성**을 직접적으로 보증합니다.

## 4. Chatbot Purpose

데이터셋과 챗봇은 명확히 구분된 목적을 가집니다:
- **데이터셋의 목적**: 역사적 사실, 주장, 선택지, 기록물 간의 지식 관계를 객관적으로 구조화하는 것
- **챗봇의 목적**: 구조화된 데이터를 활용하여 사용자가 Jesse Jackson과 유사한 정보 상황에 놓여 스스로의 판단 기준을 탐색하게 하는 것

본 챗봇은 **역사적 정답을 맞히거나 Jesse Jackson과 동일한 선택을 하도록 유도하지 않습니다.** 사용자가 당시 제공된 정보를 바탕으로 무엇을 중요하게 평가하고 어떤 가치를 우선시하는지를 가볍게 성찰하도록 돕는 것이 핵심 목적입니다.

---

## 5. Distinctive Design (핵심 차별점)

일반적인 역사 Q&A나 인물 페르소나 챗봇과 차별화되는 본 프로젝트의 4가지 핵심 설계 특성은 다음과 같습니다:

1. **제3자 해설자 시점 유지**: AI가 역사적 인물을 직접 연기하지 않고, 사건 밖의 전지적 관찰자로서 중립적인 사실과 맥락만 전달합니다.
2. **사용자 중심의 의사결정 대입**: 사용자가 직접 역사적 의사결정자의 위치에 들어가 정보를 다각도로 검토합니다.
3. **역사적 선택의 사후 공개 (스포일러 방지)**: 사용자가 자기만의 선택과 이유를 완성하기 전까지 Jesse Jackson의 실제 역사적 선택을 선제 공개하지 않습니다.
4. **단계적 정보 공개 (Progressive Disclosure)**: 초기에 모든 정보를 일시에 주입하지 않고, 사용자의 질문과 관심사에 따라 맥락 정보를 순차적으로 제공합니다.

## 6. Persona & Roles

| 구분 | 역할 정의 | 설명 |
| :--- | :--- | :--- |
| **AI Persona** | **사건 밖의 전지적 제3자 해설자** | 중립적 어조로 1996년 12월 18일 당시의 배경과 쟁점을 객관적으로 설명하며 판단을 유도하지 않음 |
| **User Narrative Role** | **시뮬레이션 의사결정자** | Jesse Jackson과 동일인이 아니며, 당시와 유사한 정보 및 선택 상황에 자신을 대입해 보는 주체 |

---

## 7. Conversation Flow (8단계 대화 흐름)

본 챗봇은 **Progressive Disclosure(단계적 정보 공개)** 방식을 통해 대화를 진행합니다.

| 단계 | 챗봇의 역할 | 실제 대화 예시 / 안내 |
| :---: | :--- | :--- |
| **1. 상황 진입** | 1996.12.18 결의안 채택 직후 상황만 단초 제시 | *"1996년 12월 18일 Oakland 교육위원회가 Ebonics 결의안을 채택했습니다."* |
| **2. 정보 탐색** | 사용자의 질문에 맞춰 필요한 맥락 정보 순차 제공 | *"Ebonics의 의미부터 알아볼까요, 아니면 결의안의 핵심 쟁점부터 볼까요?"* |
| **3. 준비 확인** | 선택을 내리기에 충분한 정보가 확보되었는지 확인 | *"이제 두 가지 선택 가능성과 예상되는 장단점을 비교해 보시겠습니까?"* |
| **4. 선택 제시** | 중립적 선택지 A/B 및 가상 득실 설명 | **Option A**: 즉시 공개 비판 / **Option B**: 공개 비판 유보 및 취지 확인 |
| **5. 이유 탐색** | 사용자가 선택을 내린 후 그 이유를 질문 | *"이번 선택에서 가장 중요하게 고려하신 판단 기준은 무엇인가요?"* |
| **6. 중립적 성찰** | 사용자의 판단 기준과 가치관을 정리 | *"신속한 문제 제기와 표준 영어 교육의 상징성을 우선시하셨군요."* |
| **7. 역사 공개** | 사용자의 동의를 얻은 후 실제 Jackson의 선택 공개 | *"실제 1996년 12월 21일 Jesse Jackson은 시카고 성명을 통해 원 결의안을 공개 비판했습니다."* |
| **8. 비교 분석** | 우열 없이 사용자 선택과 역사적 경과 비교 | *"사용자님의 신중한 접근과 달리, 당시 Jackson은 공론화 속도를 선택했습니다."* |

## 8. Fact / Interpretation / Simulation Policy

정보의 신뢰성을 담보하기 위해 본 프로젝트는 데이터 응답 기준을 4가지 범주로 엄격히 구분합니다:

- **Confirmed Fact (확인된 사실)**: 데이터셋 및 1차 기록물(LA Times, Washington Post, 상원 청문회 기록 등)에서 직접 확인되는 사건, 발언, 문서 관계.
- **Claim (주장)**: 특정 인물이나 기관(예: 오클랜드 교육위원회, 제시 잭슨)이 제기한 의견으로, 객관적 사실과 구분하여 명시.
- **Interpretation (작업자 해석)**: 데이터셋 제작자가 역사적 흐름을 바탕으로 재구성한 해석적 개념.
  - ⚠️ **주의**: **Option B(공개 비판 유보 및 취지 확인)**는 Jesse Jackson이 당시에 명시적으로 고민했다고 직접 기록된 선택지가 아니라, 12/21 공개 비판과 12/26 입장 완화 경과를 바탕으로 작업자가 구성한 가상 선택지입니다.
- **Simulation (가상 시뮬레이션)**: 사용자의 의사결정을 돕기 위해 제시되는 선택지별 예상 장단점 및 가상 득실.

## 9. Dataset Structure

현재 구축된 데이터셋은 총 **30개 인스턴스(Instances)**와 **48개 트리플(Triples)**로 이루어져 있습니다.

```text
Dilemma (잭슨: 원 결의안을 바로 공개 비판할 것인가)
 ├─ dm:hasDecisionMaker ──> Person (제시 잭슨)
 ├─ dm:hasOption ──────────> Option A (즉시 공개적으로 비판한다)
 └─ dm:hasOption ──────────> Option B (공개 비판을 유보하고 정책 취지를 확인한다)

Claim (오클랜드 교육위원회의 주장)
 ├─ dm:hasClaimant ────────> Organization (오클랜드 교육위원회)
 ├─ dm:isAbout ────────────> Concept (에보닉스)
 └─ Document (원 결의안) ──> dm:isEvidenceFor ──> Claim

Event (잭슨의 시카고 성명)
 ├─ dm:isOutcomeOf ────────> Dilemma (원 결의안 비판 딜레마)
 └─ dm:precedes ───────────> Event (Meet the Press 방송 비판)
```

## 10. Prompt Design

시스템 프롬프트 설계의 주요 핵심 원칙은 다음과 같습니다:

1. **선택지 즉시 제시 금지**: 첫 대화에서 두 선택지(A/B)를 바로 나열하지 않고, 상황 설명 후 사용자의 질문을 유도합니다.
2. **스포일러 엄격 방지**: 사용자가 자신의 선택을 결정하기 전까지 실제 Jesse Jackson의 행동(12/21 시카고 성명 등)을 공개하거나 암시하지 않습니다.
3. **단일 질문 원칙**: 대화 흐름마다 한 번에 하나의 핵심 질문만 던져 집중도를 높입니다.
4. **간결한 존댓말 문체**: 한국어 존댓말을 기본으로 2~3문장 이내의 명료한 어조를 유지합니다.
5. **사실·해석의 구분 명시**: 데이터셋에 없는 내용이나 일반 배경지식을 답변할 때는 '일반적인 배경 설명'임을 명확히 밝힙니다.

## 11. Notebook Usage

본 시뮬레이션은 Gemini Notebook 환경에서 다음과 같은 순서로 실행할 수 있습니다:

1. **API Key 설정**: 사용 환경에 Gemini API Key를 안전하게 환경 변수로 설정합니다 *(주의: API Key를 코드나 README에 직접 노출하지 않습니다)*.
2. **TTL 데이터셋 로드**: `oakebo` RDF 데이터셋(Turtle/N-Triples 포맷)을 메모리 또는 나리프(Graph) 엔진에 로드합니다.
3. **System Prompt 적용**: 위의 프롬프트 설계 원칙이 담긴 `system_prompt`를 설정합니다.
4. **대화 시뮬레이션 실행**: 데이터셋 정보와 사용자 입력을 Gemini 모델에 전달하여 대화를 진행합니다.

## 12. Limitations & Future Work

### 📌 한계점 (Limitations)
1. **내면 심리 미재현**: 본 시스템은 역사적 인물의 실제 내면 심리 상태나 감정을 재현하거나 추측하지 않습니다.
2. **가상 선택지 포함**: Option B(공개 비판 유보)는 딜레마 구성을 위해 도입된 작업자의 해석적 선택지이며, 실제 Jackson의 명시적 고민 기록은 없습니다.
3. **제한된 범위**: 1996년 12월 18일부터 1997년 1월 23일 사이의 특정 기간과 오클랜드 에보닉스 결의안 관련 핵심 기록물만을 대상으로 합니다.

### 🔮 향후 과제 (Future Work)
- 언어학자, 지역 사회 교육자, 학생 등 다양한 주체의 `Claim` 및 `Evidence` 추가 구축.
- 수사적 상황(Rhetorical Situation)의 3요소(긴급한 필요, 청중, 제약)를 다각적으로 반영한 고도화된 수사적 딜레마 모델링 확장.
